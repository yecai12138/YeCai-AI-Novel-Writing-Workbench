# 纪律清单（做之前先看这张表）

> 本文件对应项目的工程约束。每条都写成「禁止什么 / 为什么 / 怎么查」，
> 能被 `npm run contract` 机械验证的会在末尾标注检查号。

这份清单的来源是反复出现的返工模式。**新增一条的门槛**是：
它必须能对应一次真实发生过的问题；写不出「怎么查」的条目不要收进来。

## A. 进程与边界

1. **渲染进程不读盘。** 所有文件读写走后端命令；前端只用 `api`（`src/lib/ipc.ts`）。
   理由：绕过 `path_guard` 就等于绕过全部路径校验。查：`C1`。
2. **不新增第二条 IPC 出口。** 除 `src/lib/ipc.ts` 外，任何 `.ts/.tsx` 不得 `import { invoke } from "@tauri-apps/api/core"`，
   也不得直接调用 `invoke(`。理由：两条出口＝两套错误处理＝两套字段命名。查：`C1`。
3. **后端只暴露命令，不暴露实现细节。** 新命令必须 `#[tauri::command]` + 在 `lib.rs` 的 `generate_handler!` 注册。
   理由：漏注册的命令在 release 里静默不可用，dev 里也只在调用时才报。查：`C2`。
4. **路径字符串先进 `validate_root` / `rel_is_safe`。** 不拿用户给的相对路径直接 `join`。
   理由：`../` 逃逸是本应用唯一的高危面。

## B. 状态与事实

5. **不用 mtime 判断「内容是否变化」。** 需要判断改没改，比内容哈希（或 `size+hash`）。
   理由：同步工具、复制、还原都会重写 mtime，而内容可能一字未变；反过来也只写回相同内容也会变 mtime。
   mtime 只允许用于「展示」「粗略找改动候选」两种用途。
6. **不引入第二个状态事实源。** 书的状态以磁盘上的文件为准；`.storydesk/` 下的 ledger / checkpoint 只做审计与恢复线索，
   不得反过来覆盖磁盘事实。理由：双事实源一旦分歧，就再也说不清哪个是真的。
7. **不自动续跑。** 崩溃恢复由用户点「继续」，应用不擅自重放。
   理由：重放的是一段会花钱、会改文件的模型调用，代价由用户承担。
8. **写操作先写临时文件再 rename。** 不用「清空再写」。理由：中途崩溃会留下半章。

## C. 提示词与判定

9. **判定逻辑不进 prompt。** 硬规则（文件名、字数、引号、章末标记）写在代码里拼装，不指望模型记住。
   理由：prompt 里的规则会被稀释；代码里的规则不会。
10. **统计/评分不进判定。** 文风统计只作为写作提示注入正文任务，不作为章节通过与否的理由（见 `docs/文风统计.md` §4）。
11. **同一段文案只有一个组装点。** 例如写正文的提示词只由 `compose_agent_prompt` 产出，不允许别处再拼一份。
    理由：两处拼装必然漂移，且没人知道线上跑的是哪份。
12. **模型输出当不可信输入解析。** 解析失败要给出可读错误，不 `unwrap()`。

## D. 观察与诊断

13. **观察者只读。** 诊断/统计/体检类代码不写业务文件（可以写自己的日志目录），不改书稿。
    查：`stylestat` 只 `read_dir` + `read_to_string`。
14. **日志脱敏，导出前自查。** API Key、token、绝对家目录路径不进导出文件。

## E. 规格与测试

15. **改行为先改规格。** 计数口径、阈值、命名以文档为准；文档与代码不一致时，先改文档再改代码，
    并在同一次提交里让规格镜像测试通过（`docs/文风统计.md` 的句式表 ↔ `pattern_defs()`）。查：`C4`。
16. **规格镜像测试要独立于实现。** 断言用「手数出来的期望值」而不是「跑一遍实现再抄回来」，
    这样实现改错时测试才会红。例：`spec_pattern_counts_match_hand_counted_fixture`。

## F. 版本与发版

17. **版本号三处一致。** `package.json`、`src-tauri/tauri.conf.json`、`src-tauri/Cargo.toml` 必须是同一个号。查：`C3`。
18. **发版前跑 `npm run typecheck && npm run contract`。** 任一失败不发版。
